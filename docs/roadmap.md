# 息刻产品路线图

> 更新日期：2026-10-06。适用范围：Android 离线优先个人感受日记。
> 当前能力以仓库代码为基线，公开版本见 [GitHub Releases](https://github.com/hi-fullmoon/Xike/releases)。代码已实现不代表已经完成真机验收。
> 只承诺近期迭代范围，后续按用户反馈调整；版本号在确定交付范围后分配，不预设发布日期。

## 产品方向

**让用户轻松留下一刻，在未来可靠地找回和理解自己的感受。**

- **轻量记录**：只选心情也能保存，文字、照片和语音按需添加，不增加必填负担。
- **数据属于用户**：修改、删除、备份、恢复和迁移保持可靠，新增功能不得损害旧记录。
- **隐私优先**：保持无账号、本地加密和离线核心能力，联网功能由用户主动选择，并清楚说明发送的数据。
- **温和回望**：呈现统计依据，不制造打卡压力，不作心理健康诊断或未经验证的因果推断。

## 近期迭代：放心开始使用

目标：让新用户顺利完成首次记录，让已有用户能够放心升级、备份和恢复。这是当前唯一承诺的迭代范围；本路线图更新不代表以下项目已经交付。

### 使用帮助

- 完善下载、安装和覆盖更新说明。README 已补充入口与步骤，后续随发布维护。
- 补充简短的首次记录帮助，说明只选心情也可保存、如何回望和如何备份。先通过 README 与帮助文档承载，根据反馈判断是否需要应用内引导。
- 补充恢复帮助：说明替换范围、一次撤销、密码保管、换机步骤，以及文件或密码错误时的处理方式。
- 统一反馈说明，收集版本、设备、复现步骤和实际表现，提醒用户遮盖私人内容。

### 数据与使用验收

| 验证范围 | 必须确认的行为 |
| --- | --- |
| 新安装与覆盖升级 | 首次保存和回望正常；从当前公开版本升级后记录、附件与设置保留 |
| 备份、恢复与撤销 | 实际导出文件可恢复，摘要与内容一致；错误密码、截断文件和缺失附件不替换原数据；一次撤销还原原内容 |
| 草稿与附件 | 进程回收后草稿可继续；照片和语音保存、编辑、删除、撤销后的引用一致 |
| 应用锁与提醒 | 后台和重启后的锁定符合设置；明确权限拒绝、时区变化和强制停止后的实际行为 |
| 可访问性与显示 | 大字体、TalkBack、深色模式、横屏和大屏下可完成核心操作 |
| 存储与性能 | 低存储、长时间使用、大量实际记录和大备份下失败可恢复，无已知数据损坏 |

每项记录候选提交、设备、Android 版本、安装包 SHA-256、操作步骤和实际结果。性能验证还需记录数据规模和测量条件。

仓库已有相关测试代码与发布检查项，本次文档更新没有重新执行应用测试或真机验收。以上项目在取得可追溯证据前保持待验证；发现缺陷后安排有明确范围的修复。

### 完成标准

- 帮助内容与候选安装包行为一致，用户能独立完成首次记录和一次备份恢复。
- 按[发布检查清单](release-checklist.md)通过相关自动化门禁并保存真机证据；最低支持 API 与目标 API 设备均完成核心烟测。
- 无已知数据丢失、恢复错误或应用锁绕过等发布阻断问题。
- 邀请首批试用者连续使用一周，记录首次使用障碍、继续或停止使用的原因，以及回望是否有用。以获得 20 位愿意反馈的试用者为招募目标，不把人数设为发布硬门槛。

## 下一阶段：解决持续使用中的问题

近期验收完成后，依据反馈选择一个主要问题进入下一轮。以下是优先评估的候选，不同时承诺交付。

| 候选 | 进入开发的依据 | 最小范围与验收要求 |
| --- | --- | --- |
| 自定义主题 | 预设主题无法表达用户反复记录的事情 | 创建、重命名、排序、停用；明确历史记录是否随重命名变化，保证搜索、统计和备份兼容 |
| 定期加密备份 | 用户经常忘记手动备份，且有可靠文件存放需求 | 主动授权文件夹与频率、保留策略；处理授权失效、密码与密钥保管、写入失败和空间不足，验证文件能够恢复 |
| 记录与回望改进 | 多位用户遇到可复现的操作障碍，或无法找到已知记录 | 明确具体障碍，只修改对应流程；通过真实操作复验并检查影响范围 |

开发前记录需求证据、交付边界、数据兼容方案和验收方法。功能常见或竞品拥有，不构成进入开发的充分依据。

## 后续阶段：让长期记录更有价值

| 候选 | 适用场景 | 开发前必须解决的问题 |
| --- | --- | --- |
| 恢复合并 | 两台设备或多份备份均有需要保留的记录 | 记录身份、重复识别、编辑与删除冲突、附件去重、预览和失败回滚 |
| Markdown 导出 | 在其他工具中继续阅读和整理记录 | 使用标准格式与成熟依赖，保留附件、时间和主题，提供明文隐私提示；不替代完整恢复备份 |
| 桌面小组件 | 已有快捷入口仍无法满足快速记录需求 | 桌面可见内容、应用锁边界、误触和草稿衔接 |
| 回顾分享 | 主动分享选定的回望内容 | 分享预览、内容选择和隐私遮盖；现有本地回望文字不重复列为新功能 |
| 更多分发渠道 | 安装入口限制了目标用户试用 | 渠道规则、商店素材、签名升级兼容和维护能力；F-Droid 收录需另行核查依赖与构建要求 |

这些候选没有固定顺序和日期。依据实际需求选择，未获得需求证据的项目保持候选状态。

## 稳定版门槛

1.0 以质量为门槛，不要求实现所有候选功能：

- 记录、编辑、删除、回望、锁定、备份、恢复和升级有自动化结果与真机证据。
- 旧数据和备份保持兼容；失败不会损害原内容，恢复行为有明确说明。
- 核心操作在放大字体和 TalkBack 下可完成，最低支持版本与目标版本通过验收。
- 启动、滚动、搜索、附件读取和大备份有可复查的性能基线。
- 发布素材、隐私说明、签名密钥保管与恢复流程齐备，发布故障有处置方案；涉及数据库变化时，不假定旧 APK 能读取新版数据。
- 试用期间发现的发布阻断问题已解决并复验。

定期备份、恢复合并和小组件不作为 1.0 的默认前提。

## 持续约束与评审

- 数据库或备份格式变化同时交付迁移、兼容、失败恢复和附件一致性验证，禁止破坏式迁移。
- 新增联网能力先明确用途、发送数据、依赖和授权方式，不默认接入行为追踪 SDK。
- 功能修改不自动授权界面重设计；局部问题沿用现有组件，只调整必要范围。
- 验证结果区分单元测试、仪器测试、模拟器和真机，不以编译通过代替运行验收。
- 账号、自建云同步、公开内容流、生成式 AI 日记解读、独立应用 PIN 和单篇锁不进入近期计划。有真实需求时另行评估隐私、维护和恢复成本。
- 不引入连续打卡惩罚、排行榜、心理诊断或治疗建议。
- 每两周或候选版本发布前评审一次，更新已交付能力、验证证据、用户问题和下一轮范围。通过自愿访谈、Issues 和试用交流收集反馈，不要求上传日记内容。
- 对反馈记录问题、复现条件、影响、现有解决方式和实施结果，不用 Star 数量或新增页面数量衡量产品价值。
