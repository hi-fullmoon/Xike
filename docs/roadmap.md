# 息刻产品 Roadmap

> - 当前版本：`v0.5.0`（2026-08-24）
> - 适用范围：Android 离线优先个人情绪日记
> - 排期假设：1 名 Android 开发，设计与测试按需参与。时间是相对估算，版本顺序比日期更重要。

## 1. 产品方向

息刻的北极星不是“功能最多的日记”，而是：

**让用户能在十几秒内安全地留下一刻，并在未来可靠地找回和理解自己。**

路线图遵循四条原则：

1. **数据所有权优先**：先保证可修改、可删除、可迁移、可恢复，再扩展内容生产能力。
2. **隐私默认开启**：继续保持无账号、无应用自建网络服务、本地加密；任何联网能力都需要独立的隐私评审和明确授权。
3. **温和而不评判**：帮助形成记录习惯，但不使用连续打卡焦虑、情绪诊断或夸大的因果结论。
4. **先可靠，再智能**：优先建设可测试的数据链路、检索和统计，不急于引入云同步或生成式 AI。

| 能力域 | 已实现 | 当前成熟度与缺口 |
| --- | --- | --- |
| 快速记录 | 5 档心情、8 个预设主题、280 字笔记、可选本地每日问题、加密持久草稿 | 已可用；缺少编辑、删除、补记时间和自定义主题 |

## 3. 版本路线图

```text

   ↓
v0.2   内容所有权
   ↓
v0.3   找回过去
   ↓
v0.4   温和习惯
   ↓
v0.5   深度洞察
```

### v0.1.2 — 建立可信基线（1–2 周，P0）

目标：让现有首版可以稳定迭代，先消除发布和数据恢复中的明显风险。

交付：

- 增加 PR 持续集成，执行单元测试、Lint 和 Debug 构建；修正 Gradle Wrapper 执行权限，补充 JDK 17 本地环境自检。
- 设置页从 `BuildConfig` 读取真实版本，避免发布 `v0.1.1` 后仍显示 `0.1.0`。
- 恢复前展示备份摘要与将被替换的本地记录数，要求二次确认；创建可撤销的设备内安全快照。
- 补齐“含多图备份 → 恢复”“错误密码”“截断文件”“超限文件”“恢复失败不改原数据”的端到端测试。
- 建立最小发布清单：首次启动、保存、图片、锁定、导出、恢复、升级迁移。

退出标准：

- 每个合并请求自动通过测试、Lint 和构建。
- 任一恢复失败路径均不改变原记录和附件；成功恢复后可撤销一次。
- 设置页版本与安装包版本一致。

### v0.2 — 完整的数据所有权（3–5 周，P0）

目标：用户可以完整管理自己已经记录的内容。

交付：

- 新增记录详情页，支持修改心情、文字、主题、记录时间和图片。
- 支持删除记录，提供明确确认和短时撤销；附件引用与文件删除保持原子一致。
- 支持补记过去的一刻，区分“记录时间”和“最后修改时间”。
- 支持创建、重命名、排序和停用自定义主题；保留现有 8 个主题作为默认值。
- 将 Room 写操作改为明确的事务接口，并为每次 schema 变化提供迁移测试；禁止破坏式迁移。
- 将超长的单文件 UI 按记录、回顾、洞察、设置拆分，建立可独立测试的状态层。

退出标准：

- 任意记录都可查看、编辑和删除，重启后结果一致。
- 编辑/删除含 9 张图片的记录不会产生丢失引用或孤儿文件。
- 从当前公开版本升级后，记录、主题、图片和外观设置全部保留。

### v0.3 — 快速找回过去（4–6 周，P1）

目标：随着记录变多，用户仍能在几秒内找到需要的内容。

> 实施进度（2026-08-24）：月历/时间流、本地 FTS、组合筛选、结果分页、只读详情和全局 `Flow` 已完成，并加入 1 万条本地筛选基线与 Compose UI 测试；真机执行仪器测试和数据库级 1 万条性能验收仍待完成。

交付：

- 将“回顾”升级为月历与时间流双视图，显示每天的记录数和情绪概览。
- 使用 Room FTS 建立本地全文搜索，覆盖笔记与主题。
- 提供心情、主题、日期范围、是否含图片的组合筛选，并支持清空条件。
- 从洞察柱、月历日期或搜索结果跳转到对应记录列表/详情。
- 数据读取从“一次加载全部记录”演进为 `Flow` 加分页/按日期查询；建立 1 万条记录的性能样本。
- 图表和筛选结果增加 TalkBack 描述，不以颜色作为唯一信息来源。

退出标准：

- 1 万条记录基准下，常见搜索和月份切换在中端设备上无明显卡顿。
- 用户可在三步内按日期、文字、主题或心情定位一条已知记录。
- 搜索索引可从数据库重建，不进入单独的备份兼容负担。

### v0.4 — 建立温和的记录习惯（4–6 周，P1）

目标：减少“想记录但忘了、写到一半丢了”的情况，不制造打卡压力。

> 实施进度（2026-08-24）：加密草稿、照片长期读取授权、本地非精确提醒、星期/夜间勿扰/暂停、通知权限、重启与时区重排、桌面快捷入口和 3 套可关闭的本地问题库均已完成；JVM 测试、Lint、Debug APK 与 Android 测试包已通过构建。真机上的强制停止、重启、跨时区和通知拒绝矩阵仍需在发布前执行；桌面小组件按原计划等待快捷入口使用验证。

交付：

- 将未完成的心情、文字、主题和待导入图片保存为加密草稿，支持进程被系统回收后继续。
- 提供完全本地的可选提醒：时间、星期、静默时段和一键暂停；正确处理通知权限、重启和时区变化。
- 增加桌面快捷入口；根据使用验证决定是否继续投入桌面小组件。
- 每日问题可切换、关闭或从本地题库选择，不发送用户内容。
- 用“本周记录了几天”等中性反馈代替连续天数惩罚和失败提示。

退出标准：

- 强制结束应用、重启设备和跨时区后，草稿与提醒行为符合用户设置。
- 不授予通知权限时，记录、回顾、洞察和备份能力不受影响。
- 所有习惯功能默认关闭或可随时关闭，不改变离线边界。

### v0.5 — 提供可信的深度洞察（4–6 周，P1）

目标：让长期记录产生价值，同时避免把相关性描述成原因或健康诊断。

> 实施进度（2026-08-24）：心情分布、记录频率与覆盖度、前一等长周期、主题次数变化、工作日/周末对照、样本分级、原始记录下钻和设备内回顾文字均已完成；图表包含文本数值和 TalkBack 描述，不以颜色作为唯一信息。已覆盖时区、跨年、闰年、夏令时、空数据、单条记录和 1 万条记录基线；Compose 测试已编译，真机动态字体、TalkBack 与分享选择器仍需发布前烟测。

交付：

- 增加心情分布、记录频率、主题趋势、工作日/周末对比和前一周期对比。
- 展示数据覆盖度与样本量；数据不足时说明限制，不给出强结论。
- 支持从洞察下钻到构成该统计的原始记录。
- 生成完全在设备内完成的周/月回顾卡片，用户主动选择后才导出或分享。
- 为时区、跨年、夏令时、无数据、单条记录和大量记录补齐统计测试。

退出标准：

- 每个结论都可追溯到明确的统计口径和原始记录。
- 洞察文案不包含诊断、治疗建议或未经验证的因果判断。
- 同一份数据在相同时区和日期基准下可得到确定性结果。

### v1.0 — 稳定、可迁移、可发布（3–4 周，P0）

目标：达到可以长期维护并面向更广泛用户发布的质量标准。

交付：

- 支持用户授权的系统文件夹定期加密备份、保留策略和“最近一次备份是否可恢复”健康检查；仍通过系统文件提供方工作，不自建云服务。
- 恢复支持“替换/合并”预览与冲突处理；提供带隐私警告的 Markdown/CSV 明文导出。
- 增加首次使用引导、隐私说明、备份密码风险提示、数据恢复帮助和应用内版本/开源许可信息。
- 完成动态字体、TalkBack、横屏/大屏、深色模式、低存储空间和 API 26–36 设备矩阵验证。
- 建立启动、滚动、搜索、图片解码和大备份性能基线；清零发布阻断级缺陷。
- 完成商店素材、隐私披露、签名密钥恢复演练和稳定版发布回滚方案。

退出标准：

- 新安装、跨版本升级、备份迁移和回滚演练全部通过。
- 核心任务可在 TalkBack 与放大字体下完成，关键页面无阻断级布局问题。
- 公开发布前的 Beta 周期内无已知数据丢失、加密绕过或 P0/P1 缺陷。

## 4. 横向技术工作

以下工作不应被当作某个版本末尾的“优化项”，而应随功能一起完成：

| 工作流 | 持续要求 |
| --- | --- |
| 数据与迁移 | 每个 schema/备份格式变化都有正向迁移、失败回滚和旧版本样本测试；不使用 destructive migration |
| 隐私与安全 | 不新增网络权限或第三方分析 SDK，除非先完成单独提案、数据清单、威胁模型和用户授权设计 |
| 性能 | 避免每次保存后重读全部日记；列表分页、图片缩略图缓存、后台 I/O 和大数据集基准同步推进 |
| 可测试性 | 业务计算保持纯函数；数据层做仪器测试；关键 Compose 用户链路做 UI 测试；发布前用真实设备做烟测 |
| 无障碍 | 交互控件有语义，图表有文本等价描述，支持动态字体、触控尺寸和非颜色编码 |
| 文案与资源 | 界面字符串逐步迁入 Android resources，为文案复用、测试和未来本地化做准备 |

## 5. 优先级与取舍

### 必须优先（P0）

- 数据恢复安全、真实版本展示、PR 质量门禁。
- 记录详情、编辑、删除、附件一致性和数据库迁移。
- 1.0 前的无障碍、升级、备份和安全发布门槛。

### 应当随后（P1）

- 月历、搜索、筛选、分页。
- 加密草稿、本地提醒、可解释的深度洞察。
- 定期加密备份与恢复合并。

### 可按验证结果裁剪（P2）

- 桌面小组件、回顾卡片分享、明文批量导出、更多主题外观。
- 若排期紧张，优先裁剪这些项目，不裁剪数据安全、迁移或测试。

### 1.0 前明确不做

- 账号体系、自建云同步、社区或公开内容流。
- 生成式 AI 解读日记、心理健康诊断或治疗建议。
- 连续打卡惩罚、排行榜等压力型机制。
- 单篇日记锁和独立应用 PIN；继续沿用现有整应用系统身份验证边界。

这些能力并非永久排除，但都需要在 1.0 后用真实用户研究证明价值，并先解决隐私、恢复和信任成本。

## 6. 最近三个迭代建议

### 迭代 A：发布与恢复安全

- PR CI、Wrapper 权限、真实版本号。
- 备份摘要、替换确认、可撤销安全快照。
- 备份/恢复端到端测试和发布烟测清单。

### 迭代 B：记录数据层 CRUD

- DAO 的更新、删除、按 ID 查询和事务接口。
- `createdAt`/`updatedAt` 数据模型与 schema migration。
- 图片替换、删除、失败回滚和孤儿清理测试。

### 迭代 C：记录详情与编辑体验

- 详情、编辑、删除确认与撤销界面。
- 补记时间、自定义主题的最小版本。
- Compose UI 测试覆盖“新建 → 编辑 → 删除 → 撤销”。

完成这三个迭代后，再进入月历和全文搜索，可以避免检索层建立在尚未稳定的数据模型之上。

## 7. 评审节奏

- 每个版本开始前只承诺该版本的 P0/P1，P2 保持候选状态。
- 每两周检查一次范围、数据风险和用户反馈，不以新增页面数量衡量进度。
- 每个版本结束必须同时交付功能、迁移、测试、文案、无障碍语义和发布说明。
- 产品验证优先采用本地可见指标、可选的用户访谈和 Beta 反馈；在没有独立隐私设计前，不接入行为追踪 SDK。
