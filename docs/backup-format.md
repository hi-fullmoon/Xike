# 备份格式与离线阅读

导出时默认开启“使用密码加密”。开启后得到 `.xike` 文件，关闭后得到普通 `.zip` 文件。两种文件都包含同一份日记清单、媒体文件和静态 `index.html`，但 `.xike` 整体用密码派生密钥和 AES-GCM 加密，浏览器无法直接打开其中的页面。

未加密备份是单个 ZIP 文件。解压后打开根目录的 `index.html`，即可离线阅读文字、心情、主题、天气、照片、录音和视频；媒体路径相对于页面，不依赖应用、账号或网络。常见 JPEG、PNG、GIF、WebP 照片保留可识别的扩展名；浏览器不支持的媒体格式仍保存在 ZIP 中，但可能无法内嵌预览。单张照片保留比例，2 张和 4 张采用两列，其余多图采用三列网格，超过 9 张继续排列。点击照片可放大并在同一条日记内切换，支持左右方向键和 Esc 关闭。页面仅允许备份生成器自带的图片预览脚本，日记文字按 HTML 文本转义；不支持脚本或对话框的浏览器仍可点击打开原图。未加密 ZIP 和解压目录中的全部内容都是明文。

归档清单 `manifest.json` 是应用恢复的数据源，`index.html` 仅用于阅读。当前源码导出版本 8 的归档，包含 `manifest.json`、`index.html`、`images/`、`audios/` 与 `videos/` 下实际引用的附件，以及最后的 `complete.txt`。视频和 JPEG 封面一起放在 `videos/`；清单保留时长、原文件大小、MIME 类型和两个文件名。恢复前会识别加密与否，检查格式版本、每项大小、ZIP CRC、结束标记及附件是否齐全，核对视频真实时长、大小和封面尺寸，然后展示摘要并要求确认替换。替换前的本机数据仍会生成加密撤销快照。版本 4–7 的归档及更早的加密 JSON 备份继续可导入；旧版应用会拒绝版本 8，不会忽略视频后恢复。

每条记录最多包含一段视频，最长 5 分钟，最大 500 MB。视频保留 MP4、3GP、WebM、MOV 或 MKV 的原始容器格式，不自动转码；设备能否播放还取决于具体编码。全部备份视频及封面的解压总量最多 10 GB，单个封面最多 2 MB。离线阅读页提供视频播放器、封面和原文件链接；浏览器不能播放某种编码时仍可打开原文件。草稿及视频编辑草稿不会写入导出备份。

`.zip` 适合希望保存一份可读副本的用户；`.xike` 适合保存到共享设备或云盘。解压后的 HTML 不是加密文件，不能把它与加密备份混为一谈。若以后需要“浏览器输入密码直接打开单个文件”，那会是另一种带客户端解密器的格式，需要单独评估兼容性与安全性。

## 视频验证记录（2026-10-09）

JDK 17 下的 `testDebugUnitTest`、`lintDebug`、`assembleDebug` 和 `assembleDebugAndroidTest` 已通过。独立 API 36 模拟器上，使用系统摄像机实际录制的短视频验证了拍摄返回、相册选择、封面和加密播放；中文浅色常规字号，以及英文深色、320 dp 宽度、两倍字体下的视频入口、选择弹窗和播放器进行了实际显示检查。

`JournalVideoWorkflowTest` 分两个独立仪器测试进程执行：先保存视频日记、草稿和视频编辑草稿，再在新进程中读取、解密播放并跳转进度；验证 ZIP 与加密备份往返后的 SHA-256 一致性、恢复撤销、删除撤销、缺少视频时拒绝恢复，以及过期编辑副本的清理。两阶段均通过。数据库迁移、原有备份、删除撤销、草稿存储和指定页面交互的 20 项回归测试也已通过。

这些结果不代表真机、API 26、全部视频编码、接近 500 MB 的视频或实际超过 5 分钟的视频已经验收。时长和大小限制的无效元数据拒绝路径已覆盖；实际长视频、大文件性能及离线 HTML 在不同浏览器中的播放仍需补充实测。
