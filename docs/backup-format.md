# 备份格式与离线阅读

导出时默认开启“使用密码加密”。开启后得到 `.xike` 文件，关闭后得到普通 `.zip` 文件。两种文件都包含同一份日记清单、媒体文件和静态 `index.html`，但 `.xike` 整体用密码派生密钥和 AES-GCM 加密，浏览器无法直接打开其中的页面。

未加密备份是单个 ZIP 文件。解压后打开根目录的 `index.html`，即可离线阅读文字、心情、具体感受、主题、天气、照片、录音和视频；媒体路径相对于页面，不依赖应用、账号或网络。常见 JPEG、PNG、GIF、WebP 照片保留可识别的扩展名；浏览器不支持的媒体格式仍保存在 ZIP 中，但可能无法内嵌预览。单张照片保留比例，2 张和 4 张采用两列，其余多图采用三列网格，超过 9 张继续排列。点击照片可放大并在同一条日记内切换，支持左右方向键和 Esc 关闭。页面仅允许备份生成器自带的图片预览脚本，日记文字按 HTML 文本转义；不支持脚本或对话框的浏览器仍可点击打开原图。未加密 ZIP 和解压目录中的全部内容都是明文。

归档清单 `manifest.json` 是应用恢复的数据源，`index.html` 仅用于阅读。当前源码导出版本 9 的归档，包含 `manifest.json`、`index.html`、`images/`、`audios/` 与 `videos/` 下实际引用的附件，以及最后的 `complete.txt`。版本 9 保存新五档心情的独立标识、分类版本和具体感受，阅读页面按保存顺序展示具体感受。最高支持版本 8 的旧应用会拒绝版本 9，避免把新心情误读为平静或忽略具体感受。视频和 JPEG 封面一起放在 `videos/`；清单保留时长、原文件大小、MIME 类型和两个文件名。恢复前会识别加密与否，检查格式版本、每项大小、ZIP CRC、结束标记及附件是否齐全，核对视频真实时长、大小和封面尺寸，然后展示摘要和恢复方式。版本 4–8 的加密归档及更早的加密 JSON 备份继续可导入，未加密归档继续支持版本 8；更早的未加密格式仍不接受。

默认使用合并恢复：保留本机日记，补入备份中缺少的记录。同一记录标识下，日期、心情、主题、原文、天气及附件内容都一致时跳过；存在差异时保留本机版本，将备份版本作为具有独立标识的副本导入，不改写原文或日期。照片、录音、视频和封面按解密后的 SHA-256 比较，不依赖恢复时变化的文件名。冲突副本使用稳定标识，重复导入相同备份不会再次添加相同版本；若副本后来又被编辑，则保留编辑结果并另存备份版本。不同标识的独立记录不会仅因文字相同而被合并。

仍可选择“替换全部内容”，再次确认后将本机日记替换为备份内容。两种方式都会在写入前创建加密安全快照，支持撤销最近一次有效恢复；合并没有新增记录时不写入数据库或附件，也不覆盖已有撤销快照。恢复后尚未改动日记时，撤销资格可跨重启保留；成功新增、编辑、删除日记或撤销删除后，资格立即失效并清理快照，设置菜单及短时提示中的撤销入口随之消失。失败的写入、未保存草稿和外观设置不影响资格。资格标识与日记修改在同一数据库事务中提交，撤销写入时再次校验，避免旧提示或并发修改覆盖后续记录。旧快照缺少资格绑定时不再允许撤销。草稿及应用设置不参与日记合并。

每条记录最多包含一段视频，最长 5 分钟，最大 500 MB。视频保留 MP4、3GP、WebM、MOV 或 MKV 的原始容器格式，不自动转码；设备能否播放还取决于具体编码。全部备份视频及封面的解压总量最多 10 GB，单个封面最多 2 MB。离线阅读页提供视频播放器、封面和原文件链接；浏览器不能播放某种编码时仍可打开原文件。草稿及视频编辑草稿不会写入导出备份。

`.zip` 适合希望保存一份可读副本的用户；`.xike` 适合保存到共享设备或云盘。解压后的 HTML 不是加密文件，不能把它与加密备份混为一谈。若以后需要“浏览器输入密码直接打开单个文件”，那会是另一种带客户端解密器的格式，需要单独评估兼容性与安全性。

## 自动备份

“设置 → 备份与迁移 → 自动备份”支持每天或每周指定一天、自定义时分、系统授权目录和保留 1–100 份备份，默认关闭，初始计划为每周日 00:00、保留 5 份。周日 00:00 指周六结束后的午夜。

自动备份默认开启“使用密码加密”，生成 `.xike` 文件，沿用手动备份格式与恢复流程。可以关闭加密，无需填写密码，生成可解压阅读的 ZIP；拿到 ZIP 的人也能看到全部内容。首次启用加密时设置至少 8 位密码；已有密码时留空沿用，修改密码只影响之后生成的文件。关闭加密会保留已存密码，重新开启时可继续沿用；旧文件不会转换格式。密码使用 Android Keystore 保护的加密偏好存储保存在本机，不进入导出文件或日志；换机恢复加密文件仍需原备份密码。自动备份与手动备份一样，只包含已保存的日记及引用附件，不包含草稿与应用设置。

默认目录为公共“下载 / Xike”，首次备份时创建。Android 10 及以上通过 MediaStore 写入，无需额外存储权限；Android 8–9 首次启用时需要存储权限。也可以通过系统文件夹选择器更改目录，授权跨重启保留，不能选择 Android 禁止访问的位置；已选择的目录继续沿用，可以点击“使用默认目录”切回。更换目录后，旧目录文件保留；保留数量仅作用于当前目录中本功能已登记的自动备份，手动导出或其他文件不参与清理。新文件先在本机按所选加密方式生成、检查格式与内容，再写入目标目录并读回比对 SHA-256，成功登记后才清理旧文件。失败不触发旧备份清理；目录失效后重新授权即可继续使用。

任务使用 WorkManager 持久调度，独立的周期任务每 15 分钟检查本地日历截止时间，保存计划时另设一次截止时间唤醒；未到期时不读取日记。Android 12 及以上在应用后台使用普通系统任务，避免因系统禁止启动前台服务而反复失败；应用在前台或较早系统允许时，可使用前台服务并显示不含日记内容的处理通知。普通后台任务受系统执行时限约束，大体积媒体备份可能中断并重试，不能保证在一次后台运行中完成。手机重启后由系统恢复调度，时间或时区变化时重新安排；后台限制、省电模式、任务配额和强行停止应用可能延后执行，不能保证整点备份。逾期后备份一次并计算下一次时间，不补生成多个历史文件。新文件登记、成功时间、下一次时间和待清理状态一起落盘，清理中断后单独恢复，不重复导出。界面显示下次计划、上次成功时间和固定失败原因，失败会自动重试。关闭自动备份会取消后续任务并保留已有文件。

## 视频验证记录（2026-10-09）

JDK 17 下的 `testDebugUnitTest`、`lintDebug`、`assembleDebug` 和 `assembleDebugAndroidTest` 已通过。独立 API 36 模拟器上，使用系统摄像机实际录制的短视频验证了拍摄返回、相册选择、封面和加密播放；中文浅色常规字号，以及英文深色、320 dp 宽度、两倍字体下的视频入口、选择弹窗和播放器进行了实际显示检查。

`JournalVideoWorkflowTest` 分两个独立仪器测试进程执行：先保存视频日记、草稿和视频编辑草稿，再在新进程中读取、解密播放并跳转进度；验证 ZIP 与加密备份往返后的 SHA-256 一致性、恢复撤销、删除撤销、缺少视频时拒绝恢复，以及过期编辑副本的清理。两阶段均通过。数据库迁移、原有备份、删除撤销、草稿存储和指定页面交互的 20 项回归测试也已通过。

这些结果不代表真机、API 26、全部视频编码、接近 500 MB 的视频或实际超过 5 分钟的视频已经验收。时长和大小限制的无效元数据拒绝路径已覆盖；实际长视频、大文件性能及离线 HTML 在不同浏览器中的播放仍需补充实测。
