# 选择器跨应用超时保护验证

日期：2026-10-15。

## 修复与行为取舍

媒体选择器可能隐藏调用方任务，且系统没有提供本应用能够可靠读取的所有跨应用跳转事件。因此无法观察的操作使用从选择器启动起计算的保守超时，覆盖没有 Home、最近任务或锁屏事件的中断。

- 短于非立即锁定时限的正常返回或取消，继续当前会话。
- 达到锁定时限后返回，先认证，再交付暂存结果；即使调用方没有经历 `onStart`，结果回调也会检查。
- “立即”模式下，无法观察的选择器返回时需要认证。用户一直正常选择但超过时限，也会保守要求认证。
- 能够观察的操作继续使用原有任务可见性和系统事件监控。收到明确中断时，按实际后台时间判断，不沿用此前选择器耗时。
- 认证成功后，旧结果继续暂存或交付，但旧操作不能再次启用后台豁免或重复要求同一认证。重复操作不重置最早的未观察启动时间。

检查分别位于 `onStart`、`onResume` 和系统结果回调中；回调检查在结果暂存及业务交付前执行。认证后的旧结果仍沿现有存储和读权限交付流程处理，没有丢弃媒体或绕过认证。未改变页面布局、控件样式或系统权限要求。

发布清单已同步到 schema 6，并补充 5→6 迁移和完整地址字段保留检查。

## 真实系统交互

本次创建独立 API 36 模拟器 `xike_picker_security`，序列号 `emulator-5590`，1080×2400、420 dpi、字体比例 1.0。仅该设备设置临时设备凭据；凭据未写入报告或仓库。测试通过现有偏好存储配置应用锁和 1 分钟时限，冷启动解锁及超时解锁均走真实系统设备凭据认证，没有写入伪造认证状态或模拟认证回调。

`PickerTimeoutDeviceTest` 配合外部交互驱动完成：

1. 冷启动被应用锁保护，真实系统认证成功后打开应用。
2. 通过应用的照片入口打开真实系统媒体选择器，短时取消后保持解锁。
3. 再次打开选择器，通过实际系统 Activity 启动系统设置，在外部应用停留超过 65 秒。设备仍亮屏、未锁屏；应用仍认为选择器在进行且没有后台时间，证明这次中断没有进入原有 Home／最近任务检测。
4. 按返回键回到选择器并取消，应用变为锁定，真实结果仍处于待处理状态。
5. 再次通过系统设备凭据认证，待处理结果才完成交付，后台时间被清除。

最终结果 `OK (1 test)`，耗时 91.83 秒，见 [device-result.txt](device-result.txt)。这是实际系统设置跳转验证，未宣称通知点击路径已经逐项实测。系统凭据窗口限制截图，截取结果为黑色，因此不将它作为界面显示证据，也没有绕过截图保护。

修复后重新核对超时判断、结果交付顺序、已知中断和认证后豁免清理。设备证据限于 API 36 模拟器，不代表真机、API 26 或所有厂商选择器已经验收。
