# 自动备份验收记录（2026-10-17）

## 实现范围

- 设置中的“自动备份”入口；每天或每周指定一天、时分、系统授权目录、保留 1–100 份。
- 始终使用现有密码加密格式，密码存于 Android Keystore 保护的加密偏好存储；不导出草稿和应用设置。
- WorkManager 持久调度、逾期重试、时间与时区变化后的重新安排；系统允许时使用前台处理通知，Android 12 及以上的后台使用普通系统任务。
- 本机加密并检查备份内容，目标文件读回比对 SHA-256，成功登记后才清理当前目录内已登记的旧自动备份。
- 复用同一 JournalStore 实例的同步边界，协调前台修改、恢复、附件清理与后台备份。

## 实际设备端验证

使用本次独立创建的 API 36 模拟器 `emulator-5560`，应用初始为空日记状态。未创建虚构日记或使用模拟文档提供程序，目录通过真实系统文件夹选择器授权。安装同一次构建生成的应用与测试 APK，所有操作均显式指定该设备。

`AutoBackupProcessTest` 分别在独立仪器测试进程执行下列阶段，均通过：

| 阶段 | 可观察结果 |
| --- | --- |
| `configure` | 使用真实目录持久授权，经正式保存方法保存加密密码和配置 |
| `write` | 真正执行后台 Worker 三次，仅保留两份自动备份；同目录的真实手动导出文件保留 |
| `verify` | 新进程重新读取设置与备份，正确密码可检查内容，错误密码被拒绝 |
| `interruptCleanup` / `resumeCleanup` | 真正导出并校验文件，停在成功状态落盘后的边界；新进程只补做清理，成功时间不变且没有重复导出 |
| `failedCommit` | 将本应用偏好目录临时设为只读，触发真实提交失败；内存登记、成功时间与计划恢复原值，恢复权限后只清理未提交文件，旧备份保留 |
| `polling` | 修改计划后，周期任务保持同一标识，下一次检查不被延后到远期日历截止时间 |
| `concurrent` | 两个真实 Worker 同时触发，仅新增一份备份，仍保留两份 |
| `schedule` / `verifyScheduled` | 设置下一分钟的实际计划，结束仪器测试并保持桌面前台；系统在 11:19:12 完成备份，期间没有打开应用或强制执行 JobScheduler；随后新进程成功读回，继续保留两份 |
| `revoke` | 真正撤销目录持久权限后执行 Worker，记录目录不可访问；成功时间、已登记文件与磁盘上的三份文件保持不变 |

运行方式：

```bash
adb -s "${XIKE_DEVICE_SERIAL:?请指定本次独立设备}" shell am instrument -w \
  -e class com.xike.app.AutoBackupProcessTest \
  -e autoBackupIsolated true -e autoBackupPhase verify \
  com.xike.app.test/androidx.test.runner.AndroidJUnitRunner
```

其他阶段按表替换 `autoBackupPhase`；必须先通过系统选择器授权独立测试目录。`write` 要求初始自动备份登记为空；`interruptCleanup` 与 `resumeCleanup` 必须分进程依次运行。`failedCommit` 会临时修改本应用偏好目录权限，并在 finally 中恢复；`revoke` 会撤销本应用对测试目录的权限。这些阶段只能在独立验证环境执行。

`AutoBackupUiTest` 使用真实 MainActivity 和正式自动备份弹窗：检查键盘展开时操作按钮显示、非法保留数量拒绝保存、取消后配置不变。英文普通屏幕、中文深色窄屏及英文浅色窄屏均通过；窄屏实际配置为 720 × 1600、320 dpi、字体比例 1.5。

## 修复后审核

重新追踪设置保存、调度、快照、写入、读回、登记和清理顺序。当前行为如下：

- 修改计划前先确保独立周期任务已持久保存，再提交设置，最后安排截止时间唤醒。进程中断不会让已保存设置依赖旧的远期唤醒；关闭时取消两类任务。
- 新文件登记、成功时间、下一次时间和待清理状态在一次提交中保存，成功之后才清理旧文件；清理中断后只恢复清理。
- 偏好提交失败时恢复内存中的旧值，防止后续 Worker 将未落盘的成功状态用于删除判断。
- 时间回拨时重新选择最近的计划，前拨时保留一次逾期备份；普通任务也校正截止时间，覆盖未收到时间广播的情形。
- Android 12 及以上后台不强行启动前台服务；应用可见时若恰好退到后台，拒绝提升后继续使用普通系统任务。
- 不按文件名前缀删除文件。文件不存在必须由成功的空查询证明，权限或提供程序读取失败保留登记。未完成文件只按本功能登记的 URI 回收，旧目录不可访问不会阻塞新目录的备份。
- 配置保存与 Worker 执行使用同一互斥锁，日记快照与前台存储操作使用同一实例的同步锁。

上述修复经回归后，当前未发现需要继续修改的阻断问题。本次复核只调整自动备份的调度、状态提交、清理与后台执行策略，并补充测试和说明，没有修改页面布局。
