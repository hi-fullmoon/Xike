# 窗外卡片地点来源验证

日期：2026-10-20。

## 行为与兼容

新快照根据实际获取路径分别记录 `amap`、`system`、`manual`，卡片按当前应用语言显示地点来源。高德位置由系统地址服务补全时，定位路径仍为高德。天气来源继续单独保存在原 `source` 字段中，新字段不会覆盖 Open-Meteo。

地点来源作为可选字段随快照 JSON 进入草稿及备份，并通过独立数据库列保存。Room schema 从 8 升为 9，8→9 只增加可空 TEXT 列，不重建或删除表。旧快照与未知来源标识保留为空，卡片不据当前开关猜测历史来源。

备份冲突身份仅在存在来源时纳入该字段；无来源的历史内容键保持原有格式。不同来源的版本不会被错误合并；重复导入同一版本仍可去重。

## 验证结果

- JDK 17 自检、格式、177 项 JVM 测试、Lint、调试与测试 APK 构建通过；Lint 零错误、87 项警告、12 项提示。
- JVM 回归覆盖三种来源的快照／草稿／备份 JSON 往返、未知及旧来源、中英文标签，以及备份冲突去重。
- 独立 API 36 模拟器 `emulator-5560`（AVD `Xike_Pinyin_20261020`，ARM64 转译、密度 420）上，8→9 迁移测试、两项既有心情迁移测试及两项真实天气请求检查通过。高德天气路径返回 `AMAP`，天气来源仍是 Open-Meteo；该用例不伪造 SDK 定位回调，也不等同于真机高德定位验收。
- 独立加密测试数据库通过生产 DAO／实体转换写入真实手动城市天气，在另一仪器进程中重建连接并读取，验证来源与天气来源保留。两个进程 PID 不同；仅清理本次测试数据库与元数据，没有修改用户日记或草稿。
- 使用真实 Open-Meteo 城市天气和生产 `OutdoorContextCard` 检查中英文，普通浅色 411dp／1.0 字体和窄屏深色 320dp／2.0 字体均通过；地点来源与天气来源分开显示，天气文案没有文本布局溢出。测试使用服务认可的标准查询名 `Hangzhou`，不覆盖英文模式下中文城市别名检索能力。
- 测试后恢复原屏幕尺寸、字体比例、浅色模式与应用语言。旧快照不补标、系统定位标识及高德标识的序列化与翻译通过模型测试和调用路径复核；没有宣称所有来源都完成真机卡片验收。
